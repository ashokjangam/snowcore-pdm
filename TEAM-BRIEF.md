## 4. Our actual differentiator — this is the pitch

Forking a demo isn't a submission. Here is what makes it ours.

We trained a real classifier to replace the quickstart's fake "failure probability." It
scored **worse than random** on a proper time-based holdout. Instead of tuning it, we read
the data generator and found this:

```sql
WHEN UNIFORM(0, 100, RANDOM()) < 2 THEN 1   -- emergency repair: 2% coin flip
```

**Failures in Snowflake's reference dataset are a 2% daily coin flip with no reference to
any sensor reading.** Not temperature, not vibration, not health. The prediction target was
statistically independent of every feature — so no model could ever exceed AUC 0.5. The
demo cannot do the thing it advertises.

We rewrote the generator so failures come from a **hazard rate driven by equipment health**,
kept the overall failure rate the same, and retrained the identical model:

| | Before | After |
|---|---|---|
| **Chronological holdout AUC** | **0.465** (random) | **0.766** |

Then we chose the operating threshold by **minimising expected cost**, using parts, labour
and lost-production figures from the warehouse's own maintenance records:

| Strategy (83-day holdout) | Cost |
|---|---|
| Inspect everything | $9.00M |
| Inspect nothing | $7.65M |
| **Our model** | **$5.38M** |

**Halves inspection volume, catches 88% of failures, beats inspect-everything by 40%.**

We also found and fixed **four semantic-view descriptions** that told Cortex Analyst this
was a *finance* dataset — `FAILED_IN_NEXT_7_DAYS` was documented as *"whether the customer
failed to make a payment."* That made the AI answer the wrong question.

> **The narrative:** *"We found that Snowflake's own reference data couldn't support the
> claim it was making, proved it, fixed it, and measured the difference."* That is far more
> memorable than another dashboard tour.

## 5. Getting your environment up — please do this first

Everyone should be able to run the stack. Budget **90 minutes**. These are the exact traps
that cost time; each one is a real error we hit.

**⚠️ Use the hackathon signup link from the Hack2skill email.** The organisers said this
explicitly: *"if you use the generic Snowflake trial registration, you'll not get access to
CoCo. No AI features or even the container services ready."* A normal snowflake.com trial
is useless for this.

**1. Install CoCo CLI** (Windows PowerShell — no admin needed):
```powershell
irm https://ai.snowflake.com/static/cc-scripts/install.ps1 | iex
```
The command is `cortex`, **not** `coco`. If it says "not recognized", the installer failed
to set PATH — run `$env:Path += ";$env:LOCALAPPDATA\cortex\bin"` and open a fresh window.

**2. Config goes in `connections.toml`, NOT `config.toml`.** CoCo v1.1.87 only reads
connections from `~/.snowflake/connections.toml`. Wrong file = silent failure. Note the
section header has no `connections.` prefix:
```toml
[hackathon]
account = "<ORG>-<ACCOUNT>"     # from your Snowsight URL: app.snowflake.com/<org>/<account>
user = "<YOUR_USERNAME>"
role = "ACCOUNTADMIN"
```

**3. Choose OAuth, not SSO.** SSO fails with `Error 390190: SAML Identity Provider` — trial
accounts have no identity provider. OAuth is literally labelled *"Recommended for trial
accounts."*

**4. Turn off the Claude Code MCP import.** On first launch CoCo tried to authenticate to
our corporate **Datadog** server — it auto-imports MCP servers from `~/.claude.json`. Add
to `~/.snowflake/cortex/settings.json`, then `/restart`:
```json
{ "importClaudeMcpServers": false }
```
**Do not complete that Datadog login.**

**5. Build the warehouse.** Clone our repo and run `sql/01_setup_snowcore.sql` in a
Snowsight worksheet (Run All, ~10 min). **Use our version, not upstream's** — ours has the
trial fixes and the causality patch.

**6. Streamlit needs `environment.yml`, not `requirements.txt`.** Trials can't use SPCS, so
the app runs on the warehouse runtime, which reads conda config. And **pin the Streamlit
version** or you get `AttributeError: module 'streamlit' has no attribute 'fragment'`.

Full error-by-error detail is in the Day 1 and Day 2 diaries — ask me for them.

### Why "verified queries" is a real job, not filler
The Snowflake lead called them *"a very, very crucial part"* and said it applies to **all
five** problem statements. They're what make Cortex Analyst answer consistently instead of
improvising SQL. This is high-scoring, genuinely parallel work.

### Why the demo is a real job
**Pre-recorded demos are not accepted at the finals** — it must be live. A team that hasn't
rehearsed is the most common way to lose a shortlist place.

### A known defect someone should own
OEE **Performance** in the quickstart is literally `UNIFORM(80,98,RANDOM())` — fabricated,
not computed. Real formula is *Actual Output ÷ Theoretical Max Output*. Fixing it means
adding a `THEORETICAL_RATE_UNITS_PER_HR` column to `DIM_ASSET`. Manufacturing judges will
notice this.
